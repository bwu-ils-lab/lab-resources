2. 基础概念：模仿学习、ACT、VLA与世界模型

2.1 什么是模仿学习

模仿学习的核心是让机器人从专家示范中学习“在某种观察下应该执行什么动作”。本项目中的专家是遥操作 Alicia-D 的人，示范由两路相机、Alicia-M 当前状态以及实际下发动作共同组成。

observation（图像 + 机器人状态） → expert action（关节 + 夹爪动作）

2.2 ACT 的定位

ACT（Action Chunking with Transformers）是一种视觉条件下的机器人模仿学习策略。它不是轨迹播放器，而是一个从当前观测到未来动作序列的策略网络。ACT 一次预测若干连续动作，即“动作块”，以降低长任务的有效决策长度并提高动作连续性。[2][3]

πθ(I_t, q_t) → â_t, â_{t+1}, …, â_{t+K-1}

ACT模型在时刻读取当前相机画面和机械臂状态，然后一次性预测未来连续步的机械臂动作。

项目

ACT 中的含义

I_t

当前 front 与 wrist 相机图像

q_t

Alicia-M 当前关节和夹爪状态

â

模型预测的关节与夹爪动作

K

一个动作块包含的未来动作步数

2.3 ACT 不只是“依葫芦画瓢”

ACT 确实以专家动作为监督目标，但它学习的是条件映射，而不是按时间回放某一条录像。只要药盒位置、相机视角和机械臂状态仍处于训练数据覆盖范围，模型可能生成训练集中没有完全出现过的新轨迹；但当场景、物体或起始姿态偏离训练分布较大时，成功率会明显下降。

准确定位：ACT 是训练分布内的专用视觉动作策略，擅长固定机器人、固定任务和有限场景变化，不等于通用机器人智能。

2.4 ACT 与 VLA 的边界

VLA（Vision-Language-Action）强调视觉、语言和动作的联合建模。典型 VLA 会把自然语言指令作为真正的模型输入，并通过大规模多任务预训练获得语义与泛化能力；适配新机器人时常从预训练参数开始微调。OpenVLA 等工作即采用大规模机器人示范预训练，再面向新设置进行微调。[4]

判断边界：是否使用 Transformer 不是关键；关键是语言是否真正进入模型、是否在多任务数据上学习，以及不同语言是否会产生不同动作。

2.5 什么是世界模型

世界模型关注“执行某个动作后，环境会怎样变化”。它通常学习动作条件下的未来状态、未来图像或潜在表示，可用于预测、规划、仿真和评估。[5]

world model：当前状态 s_t + 动作 a_t → 未来状态或未来图像 s_{t+1}

2.6 学习 ACT 对 VLA 与世界模型的启发

理解机器人数据不是单独的视频，而是图像、状态、动作、时间戳与episode边界的同步组合。

理解observation与action的时间对齐；模型再大，图像和动作错位仍然无法正确学习。

理解动作表示：关节绝对位置、增量、末端位姿、速度和动作块会直接影响学习难度。

理解训练与推理分布偏移：推理时模型会进入由自身动作产生的新状态，误差会逐步累积。

理解真机闭环：相机读取、状态读取、模型推理、动作下发、控制频率与安全限幅。

同一份序列数据既可训练ACT的观察→动作，也可用于世界模型的状态+动作→未来状态。

本项目为什么先做 ACT：当前数据是固定机械臂、固定双相机、单一药盒任务和 30 条示范，最适合先跑通专用策略的完整闭环；完成后再扩展多任务语言数据，微调 VLA，或研究未来状态预测。

6.4 数据质量标准

每条 episode 从相近的安全起始姿态开始，并完整完成抓取、抬起、移动和放置。

保留成功、流畅且目标明确的示范；失败、长时间停顿、无关动作和碰撞应重录。

人可以直接看真实药盒操作，但模型所需信息必须同时出现在两路相机画面中。

相机和机械臂底座在正式采集、训练数据生成和推理期间尽量保持不变。

9. ACT 训练、监控与检查点管理

9.1 训练命令

玄雅官方推荐首次 ACT 训练使用 50000 步、每 5000 步保存一次，并关闭仿真评估。[1] 官方示例 batch size 为 16；本项目 RTX 4090 实际使用 32。

SOURCE / COMMAND
source /workspace/miniforge3/etc/profile.d/conda.sh
conda activate alicia_act
cd /workspace/alicia_act/lerobot

DATASET_NAME=medicine_box_keyboard_test_v0
DATASET_ROOT="/workspace/alicia_act/data/$DATASET_NAME"
OUTPUT_DIR="/workspace/alicia_act/outputs/act_medicine_box_v0"
LOG_DIR="/workspace/alicia_act/logs"
LOG_FILE="$LOG_DIR/act_medicine_box_v0.log"

mkdir -p "$LOG_DIR"

nohup env \
  CUDA_VISIBLE_DEVICES=0 \
  PYTHONUNBUFFERED=1 \
  lerobot-train \
    --dataset.repo_id="labuser/$DATASET_NAME" \
    --dataset.root="$DATASET_ROOT" \
    --dataset.video_backend=pyav \
    --policy.type=act \
    --policy.device=cuda \
    --policy.push_to_hub=false \
    --output_dir="$OUTPUT_DIR" \
    --job_name=act_medicine_box_v0 \
    --steps=50000 \
    --batch_size=32 \
    --save_freq=5000 \
    --log_freq=100 \
    --eval_freq=0 \
    --wandb.enable=false \
  > "$LOG_FILE" 2>&1 &

TRAIN_PID=$!
echo "$TRAIN_PID" > /workspace/alicia_act/act_medicine_box_v0.pid

9.2 训练过程如何理解

从 30 条演示中随机抽取一批时间点和对应动作块。

读取 front、wrist 图像和当前机器人状态。

ACT 预测未来连续关节与夹爪动作。

将预测动作与专家真实动作比较，计算 loss。

反向传播并更新一次模型参数；这就是 1 个 training step。

50000 步的含义：不是 50000 次真机任务，也不是 50000 条数据，而是对模型参数进行 50000 次批量更新。

11.2 推理流程

推理阶段不再由人拖动 Alicia-D。系统读取实时 front / wrist 图像和 Alicia-M 当前状态，ACT 输出动作块，Alicia-M 执行后再读取新观测，形成闭环。

实时图像 + 当前关节状态 → ACT → 未来动作块 → Alicia-M 执行 → 新观测

11.3 第一次推理前的安全要求

清空机械臂周围杂物，准备随时断电或急停。

重新检测相机和串口，不能沿用过期的 /dev/video* 与 /dev/ttyACM*。

保持640×480、30 FPS、采集时的相机位置、机械臂起始姿态、药盒区域与采集阶段一致。

11.4 单回合安全推理命令

SOURCE / COMMAND
source ~/miniconda3/etc/profile.d/conda.sh
conda activate lerobot
cd ~/lerobot

FRONT_CAMERA=/dev/video4
WRIST_CAMERA=/dev/video10
FOLLOWER_PORT=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B8F042937-if00

lerobot-record \
  --policy.path="$POLICY_PATH" \

  --robot.type=alicia_m_follower \

  --robot.id=alicia_m \
  --robot.max_relative_target=8 \
  --teleop.type=alicia_d_leader \
  --teleop.port="$LEADER_PORT" \

12. 推理评估、补采与迭代

第一次能运动只说明模型成功加载，不能直接说明任务已经稳定。建议至少测试 10 次，记录成功阶段与失败阶段。

评估项

记录内容

起始条件

药盒位置、目标区域、机械臂初始姿态

接近阶段

能否找到并接近药盒

抓取阶段

夹爪是否对准、闭合时机是否正确

抬升阶段

是否稳定夹持、是否掉落

搬运阶段

路径是否安全、是否偏离

放置阶段

是否到达目标区并正确松开

结果

成功 / 失败及失败原因

失败表现

优先处理

无法找到药盒

增加不同药盒位置和视觉覆盖的数据

接近但抓空

增加对准、慢速接近与闭合时机示范

夹住后掉落

增加稳定夹持、抬升与运输示范

偏离后无法恢复

补采从轻微偏差状态恢复的演示

相机稍动即失败

恢复相机位姿，或系统性采集有限视角变化

完整研发闭环：采集 → 训练 → 单回合推理 → 失败分类 → 定向补采 → 重新训练 → 成功率评估。第一次训练通常不是终点，而是开始定位数据覆盖问题。
